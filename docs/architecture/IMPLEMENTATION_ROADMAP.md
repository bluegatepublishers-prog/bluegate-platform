# Implementation Roadmap

This table is the official delivery order, not by itself a claim of implementation. Implemented modules retain dedicated QA checklists. Classroom Assignments is implemented behind the existing disabled-by-default `ASSIGNMENTS` publisher feature and remains release-pending until `docs/testing/ASSIGNMENT_QA.md` is approved. The operational stabilization pass keeps publisher content separate from school-owned sessions, classes, staffing, enrollment, adoptions, assignments, and submissions; its acceptance workflow is in `docs/testing/OPERATIONAL_STABILIZATION_QA.md`. A phase begins only after its dependencies and business decisions are approved. Every phase requires additive migrations where needed, server-derived ownership, denial-path tests, observability, and rollback notes.

## Delivery gates

Before each release: approved ADRs and data classification; reviewed SQL/backfill metrics; type-check/build/unit/integration/migration tests; direct API denial tests; staged smoke tests for every role; documented rollback. Do not combine critical phases merely to shorten delivery time.
