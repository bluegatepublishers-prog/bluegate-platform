# Purpose

The SARTHI Design System establishes the visual language, interaction patterns, accessibility standards, and reusable UI components used across the platform.

The goal is to provide a consistent, intuitive, and accessible experience for every user.

---

# Design Philosophy

The design of SARTHI should reflect the following values:

- Simplicity
- Clarity
- Consistency
- Accessibility
- Trust
- Professionalism
- Efficiency

Every interface should help users accomplish tasks with the fewest possible steps.

---

# User Experience Principles

Every screen should answer:

**"What is the next best action for this user?"**

Interfaces should:

- Reduce cognitive load.
- Minimize unnecessary choices.
- Use plain language.
- Provide immediate feedback.
- Support keyboard and touch interaction.
- Work well on all screen sizes.

---

# Design Goals

The platform should feel:

- Modern
- Professional
- Educational
- Friendly
- Fast
- Reliable

The interface should avoid unnecessary visual complexity.

---

# Responsive Design

SARTHI supports:

- Mobile
- Tablet
- Laptop
- Desktop
- Large Displays

Every page should adapt gracefully to different screen sizes.

---

# Accessibility

The platform should follow WCAG 2.2 AA where practical.

Accessibility includes:

- Keyboard navigation
- Screen reader support
- Focus indicators
- Sufficient color contrast
- Scalable text
- Semantic HTML
- Accessible forms

Accessibility is a core requirement, not an enhancement.

---

# Color System

Colors should communicate meaning.

Primary

Used for:

- Main actions
- Navigation
- Branding

Secondary

Used for:

- Supporting elements

Success

- Confirmations
- Completed actions

Warning

- Caution
- Pending states

Error

- Validation failures
- Critical issues

Neutral

- Backgrounds
- Borders
- Text

Avoid using color as the only indicator of meaning.

---

# Typography

Typography should prioritize readability.

Hierarchy:

- Display
- Heading 1
- Heading 2
- Heading 3
- Body
- Caption
- Labels

Text should remain legible on all supported devices.

---

# Icons

Icons should:

- Be consistent
- Be recognizable
- Support text labels
- Never replace essential text

Use icons to reinforce meaning rather than replace it.

---

# Layout

The interface should use a consistent layout system.

Major elements:

- Header
- Navigation
- Content Area
- Sidebar
- Footer
- Action Bar

Spacing should follow a consistent scale.

---

# Navigation

Navigation should be:

- Predictable
- Role-based
- Searchable
- Responsive

Users should always know where they are and how to return.

---

# Forms

Forms should:

- Use clear labels
- Validate inputs immediately where appropriate
- Display helpful error messages
- Preserve entered data after validation errors
- Support keyboard navigation

Required fields should be clearly indicated.

---

# Buttons

Button hierarchy:

Primary

Main action.

Secondary

Supporting action.

Tertiary

Low emphasis.

Danger

Destructive action.

Buttons should use action-oriented text.

Example:

- Save
- Publish
- Submit
- Approve
- Download

Avoid vague labels such as "Click Here."

---

# Cards

Cards should present related information together.

Examples:

- Books
- Resources
- Students
- Teachers
- Analytics

Cards should maintain consistent spacing and structure.

---

# Tables

Tables should support:

- Sorting
- Filtering
- Pagination
- Responsive behavior
- Bulk selection where appropriate

Large datasets should remain usable.

---

# Empty States

Empty states should:

- Explain why nothing is shown.
- Suggest the next action.
- Avoid leaving blank screens.

Example:

"No resources have been uploaded yet."

---

# Loading States

Loading indicators should communicate progress.

Use:

- Skeleton screens
- Progress indicators
- Spinners where appropriate

Avoid blocking the interface unnecessarily.

---

# Error States

Errors should:

- Explain the problem.
- Suggest recovery steps.
- Avoid technical jargon.

Users should know what they can do next.

---

# Notifications

Notification types:

- Success
- Information
- Warning
- Error

Notifications should be concise and actionable.

---

# Dashboard Design

Dashboards should prioritize:

- Key metrics
- Recent activity
- Pending tasks
- Quick actions

Information should be organized by importance.

---

# Search Experience

Search should support:

- Autocomplete
- Filters
- Recent searches
- Saved searches

Search should remain fast even with large datasets.

---

# Reusable Components

Examples:

- Buttons
- Inputs
- Selects
- Modals
- Tabs
- Accordions
- Tooltips
- Alerts
- Cards
- Tables
- Pagination
- Breadcrumbs
- Dialogs

Components should be reusable across the platform.

---

# Dark Mode

The design system should support:

- Light Mode
- Dark Mode

Both themes should maintain accessibility and readability.

---

# Mobile Experience

Mobile users should be able to complete essential tasks without switching to a desktop.

Touch targets should be large enough for comfortable interaction.

---

# Internationalization

The interface should support:

- Multiple languages
- Right-to-left layouts
- Localized date formats
- Localized number formats
- Localized currencies

---

# Future Design Goals

The design system should evolve to support:

- Voice interfaces
- AI interactions
- Wearable devices
- Interactive whiteboards
- Smart classrooms
- Emerging accessibility technologies

---

# Guiding Principle

A great design system is invisible.

Users should focus on learning, teaching, and collaboration—not on figuring out how the software works.

Every component should contribute to a consistent, accessible, and trustworthy educational experience.
